so the age X25519 recipient format is implemented on OTP `:crypto`. Worktree:
`.flai-cache/worktrees/S-0003`, branch `story/S-0003`.

## Decisions

- Task layers: T-0018 (age on `:crypto`) alone; T-0019 (`Signet.SopsEncrypt`) after it,
  because it wraps the data key with `Signet.Age`; T-0020 (sops integration test in Docker)
  and T-0021 (docs and tech records) together after T-0019, because both describe or
  exercise the finished document and share no path. The sops version (3.13.3, the latest
  release) is fixed up front so T-0021 need not wait for T-0020.
- Age is hand-implemented on `:crypto` (X25519, HKDF-SHA256 over HMAC, ChaCha20-Poly1305)
  rather than a hex package: none is maintained, and the story notes anticipate this.
- The YAML document is rendered by hand, as the Go client's fixed shape allows, rather
  than adding a YAML dependency.
- The test-support age decryptor lives in `test/support`, not `lib`: the client never
  decrypts; the decryptor exists so behaviour tests can round-trip without an age binary.
- T-0010, T-0011, and T-0012 were cancelled as duplicates: the first `flai task new` batch
  created them while its output parsing failed, and the retry created T-0019 to T-0021.
- The sops round-trip is an integration test under `client-elixir/tests/integration/`,
  run by `make integration` in Docker with a pinned sops binary, as `code-quality.md`
  places it; `make test` stays free of it.
