# S-0001 Elixir client: generated stubs, admin access, and SPIFFE workload access

## Context

The operator asked for an Elixir client for signet that is SPIFFE/SPIRE compatible. The Go client is the reference design; the Erlang folder's README records that Buf's registry has no BEAM plugin. This story delivers the connection layer (generated stubs, admin access, SPIFFE workload access); S-0002 and S-0003 carry restart coordination and SOPS encryption.

## Decisions

- One story for the connection layer rather than one per concern: every story on a new component touches the same files, and a later story branches from main, so sequential stories would each wait for acceptance of the last.
- Local `protoc-gen-elixir` as a `local:` buf plugin inside a Docker toolchain image, generated code gitignored: no BSR plugin exists for Elixir, and the safety convention forbids installing a toolchain on the host.
- `grpc` 1.0 with the `gun` adapter, not Mint: only the Gun adapter opens Unix sockets, which the Workload API needs. The CVE-2026-43966 advisory on `gun`/`cowlib` is recorded in `design/tech/grpc-elixir.md` as unreachable from this client's fixed ASCII headers.
- `Signet.Spiffe.X509Source` is a GenServer that keeps following the Workload API stream, started unlinked and linked only once up, so a failed start is an error value to the caller as in Go, never an exit.
- Server authorisation is a `verify_fun` checking the single SPIFFE URI SAN's trust domain, with `server_name_indication: :disable`, mirroring go-spiffe's `AuthorizeMemberOf`; this is what the Python client could not do.
- Test certificates are signed with SHA-256 explicitly: `:public_key.pkix_test_data` defaults to SHA-1, which TLS 1.3 refuses with an unhelpful `unable_to_supply_acceptable_cert`.
- The Workload API proto is vendored verbatim from go-spiffe (Apache-2.0) with a header comment, generated under `Spiffe.Workload` via `package_prefix`.
- A `.markdownlintignore` excludes `client-elixir/deps` and `_build`, which the repository's `**/*.md` lint glob would otherwise scan once dependencies are fetched.
